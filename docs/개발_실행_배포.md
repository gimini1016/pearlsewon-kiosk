# 펄세권 개발 · 실행 · 배포

디자인 요구사항과 피드백은 [디자인팀 구현 가이드](../디자인팀_구현가이드.md)를 기준으로 봅니다. 이 문서는 소스를 실행하고 수정 결과를 확인하는 방법을 정리합니다.

## 실행

로컬은 Python 3.12 이상을 사용합니다. Vercel 환경은 `pyproject.toml`, `.python-version`, `uv.lock`에 Python 3.12로 고정되어 있습니다. Python 서버는 표준 라이브러리로 동작하며 별도 패키지 설치가 필요하지 않습니다.

저장소 루트에서 실행합니다.

```sh
python3 scripts/build.py
python3 -m backend.server --open
```

Mac에서는 `run.command`를 실행해도 됩니다. 화면 수정 후 빌드를 다시 실행하고 브라우저를 새로고침합니다. 서버 로직을 바꿨다면 서버도 재시작합니다.

기본 주소는 `http://127.0.0.1:8765`입니다. 생성된 `dist/index.html`을 파일로 직접 열면 버튼과 규칙 기반 주문 시연을 사용할 수 있습니다. 실제 AI 채팅은 서버 주소에서 사용합니다.

## API 키

다른 기기에서는 `.env.example`을 저장소 루트의 `.env`로 복사한 뒤 `OPENAI_API_KEY`를 설정합니다. 기본 모델은 `gpt-4.1-mini`이며 `OPENAI_MODEL`로 바꿀 수 있습니다. 환경변수로 직접 설정해도 됩니다.

설정 우선순위는 프로세스 환경변수, 설정 파일입니다. 설정 파일은 `PEARL_ENV_FILE`에 지정한 경로를 우선하고, 지정하지 않으면 저장소 루트의 `.env`를 읽습니다. 기존 작업 기기에서는 루트 `.env`가 없을 때 `~/Documents/생성형ai/펄세권/.env`를 사용합니다.

`.env`와 Vercel 로컬 연결 정보는 Git에서 제외합니다. API 키는 브라우저 코드·Markdown·캡처에 넣지 않습니다. `/api/health`는 키 설정 여부만 반환합니다.

## 파일 역할

| 폴더 | 핵심 파일 | 역할 |
| --- | --- | --- |
| `frontend/` | `index.html`, `base.css`, `styles.css` | 화면 틀, 공통 토큰, 화면별 배치 |
| `frontend/` | `base.js`, `screens.js`, `ai-client.js` | 공통 규칙·추천, 화면·그림·상태, AI 연결 |
| `backend/` | `server.py` | 로컬 서버, 자료 검색, 모델 호출, 주문 규칙 검증 |
| `backend/` | `vercel_handler.py` | 배포 환경의 요청 호스트·출처 확인 |
| `api/` | `chat.py`, `health.py` | Vercel 함수 진입점 |
| `scripts/` | `build.py`, `build_rag_docs.py` | HTML 조립, 검색 문서 재생성 |
| `tests/` | `test_server.py`, `test_hosted.py`, `browser/` | 주문 규칙·배포 요청·화면 동작 검사 |

빌드 과정은 데이터 → 공통 코드 → 화면 코드 → AI 클라이언트 순서로 합칩니다. `frontend/index.html`의 두 삽입 위치에 CSS와 JavaScript를 넣고 `dist/index.html` 한 개를 생성합니다. 문법 검사용 JavaScript는 `artifacts/app.js`에 만듭니다.

기존 `templates/`와 루트에 흩어져 있던 화면·서버·검사 파일은 역할별 폴더로 옮겼습니다. 이전 `requirements.md`의 디자인 요구사항은 루트의 디자인 가이드로 통합했습니다. 중복 생성물 `dist/prototype.html`과 오래된 검사 결과·캡처는 제거했습니다. 실행에 쓰는 데이터와 Vercel 설정은 유지합니다.

## 데이터와 AI 처리

`data/`에는 메뉴 26개, 토핑 6종, 추가 옵션 6종과 매장·표현 사전·검색 문서를 보관합니다. 자료를 갱신하고 검색 문서도 바꿔야 할 때만 아래 명령을 실행합니다.

```sh
python3 scripts/build_rag_docs.py
python3 scripts/build.py
```

서버는 `rag_docs.jsonl`에서 관련 문서를 로컬 문자 단위 검색으로 찾아 현재 주문과 함께 OpenAI Responses API에 전달합니다. 벡터 DB와 외부 문서 업로드는 사용하지 않습니다. 구조화된 응답을 받은 뒤 메뉴·품절·옵션·가격을 서버에서 다시 검증합니다.

대화는 최근 10개 메시지까지 요청에 포함합니다. 전화번호 입력 상태는 보내지 않으며 API 응답 저장 옵션은 `store: false`입니다. API 호출이 실패하면 오류를 안내하고 주문을 유지합니다. 규칙 응답을 실제 AI 응답처럼 대신 표시하지 않습니다.

결제·직원 호출·문자·알림톡은 시연입니다. 전화번호는 입력 중 메모리에만 두고 완료 화면에는 마지막 네 자리만 남깁니다. 서버에 주문을 저장하거나 실제 매장으로 전달하지 않습니다.

## 검사

일반 수정 뒤에는 저장소 루트에서 빌드·문법·서버 검사를 실행합니다.

```sh
python3 scripts/build.py
node --check artifacts/app.js
python3 -m unittest discover -s tests
```

서버 검사에는 주문 규칙, 가격, 품절, 옵션 제한, 요청 출처, 상태 응답에서 키를 숨기는 동작이 포함됩니다. 외부 AI 호출 없이 실행됩니다.

브라우저 검사에는 Node.js 22 이상과 Chrome이 필요합니다. 로컬 서버를 켜고, 별도 Chrome 프로필에서 원격 디버깅 포트 9223을 열어 실행합니다. Mac 예시는 다음과 같습니다.

```sh
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --no-first-run --no-default-browser-check \
  --user-data-dir=/private/tmp/pearlsewon-browser-profile \
  --remote-debugging-port=9223 about:blank
```

다른 터미널에서 실행합니다.

```sh
node tests/browser/ui-check.mjs
```

이 검사는 규칙 기반 모드로 주문·옵션·대화·테마·장바구니·알림 흐름을 확인합니다. API 사용료가 발생하지 않습니다. 결과는 `artifacts/ui-verification.json`, 캡처는 `artifacts/screenshots/`에 생성됩니다.

실제 모델 연결이 바뀌었거나 API 동작을 확인해야 할 때 아래 검사를 사용합니다. 실제 AI 요청 세 번을 보냅니다.

```sh
node tests/browser/ai-check.mjs
```

결과는 `artifacts/ai-verification.json`에 남습니다. 검사 결과와 캡처는 Git에 넣지 않습니다. 자동 검사는 실제 키오스크의 접근성·사용성 검증을 대신하지 않습니다.

## GitHub와 Vercel

공개 저장소: [gimini1016/pearlsewon-kiosk](https://github.com/gimini1016/pearlsewon-kiosk)

시연 주소: [pearlsewon-kiosk.vercel.app](https://pearlsewon-kiosk.vercel.app)

Vercel은 저장소의 `main` 브랜치와 연결되어 있습니다. `main`에 push하면 자동 배포됩니다. 설정은 `vercel.json`에 있으며 빌드 명령은 `python3 scripts/build.py`, 정적 결과 폴더는 `dist`입니다. Python API 함수에는 `backend/`와 `data/`가 함께 포함됩니다.

Vercel 프로젝트 환경변수에 `OPENAI_API_KEY`를 등록하고, 필요하면 `OPENAI_MODEL`을 지정합니다. 실제 키는 GitHub에 올리지 않습니다. `.vercel/`은 로컬 연결·빌드 정보이므로 공유 대상에 포함하지 않습니다.

배포 후 화면 주소와 `/api/health`를 확인합니다. 실제 AI 요청을 확인할 때는 ‘블랙 밀크티, 당도 30%’처럼 메뉴와 변경값이 분명한 주문으로 화면·재료·금액을 함께 확인합니다.
